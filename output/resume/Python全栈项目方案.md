## 与目标简历对应的进阶版本

完成下方最小业务闭环后，再补齐目标简历中承诺的工程能力：

- 前端恢复：保存任务 ID 和计时状态；服务端时间作为计时依据，测试刷新、断网和请求失败后的恢复。
- Docker Compose 与 GitHub Actions：完成迁移、健康检查、服务启动、后端测试和前端构建流水线。

## 定位

复用已有备考陪伴产品的真实场景，开发一个前后端分离的 Python 全栈版本。第一个项目突出 Agent 编排、检索和工具调用，第二个项目重点展示业务建模、接口设计、认证授权、数据库和交付能力。AI 复盘作为增量功能，先完成不依赖模型的业务闭环。

## 技术栈与范围

- 后端：Python、FastAPI、Pydantic、SQLAlchemy、Alembic。
- 数据库：PostgreSQL；开发和部署均使用同一数据库类型。
- 前端：React、TypeScript、Vite；复用已有前端需先确认代码和数据格式。
- 认证：密码哈希与短期 JWT 登录凭证。所有目标、专注记录和复盘接口按登录用户过滤数据，不接受客户端指定资源所属用户。
- 交付：Docker Compose 管理前端、后端和数据库；pytest 验证关键接口。

不在第一版引入 Redis、Celery、多 Agent、微服务或支付，避免扩大范围而无法完成。

## 最小业务闭环

1. 用户注册和登录，创建长期目标、阶段目标、每日任务。
2. 启动或结束专注记录，保留开始时间、结束时间与关联任务。
3. 按日和周汇总专注时长、任务完成数与目标进度。
4. 保存文本复盘；可选调用 DeepSeek，根据用户授权读取当日汇总生成建议。
5. 在浏览器完整演示上述流程，重启服务后数据仍保留。

## 数据模型

- users：账号、密码哈希、创建时间。
- goals：用户 ID、父目标 ID、标题、目标层级、期限、状态。
- focus_sessions：用户 ID、关联目标 ID、开始和结束时间。
- daily_reviews：用户 ID、日期、用户复盘文本、AI 建议。

时间以带时区时间存储，日汇总明确使用 Asia/Shanghai。目标父子关系必须属于同一用户，并限制层级及循环引用。每日复盘在用户和日期上建立唯一约束；按用户、日期检索的记录增加对应索引。
