# Mini 交互与 SQL 正确性改进（2026-10-01）

## 排查结论

用户消息延迟的原因在 `frontend/src/App.vue`：发送后清空输入框，但等服务端完成整轮执行才拿到消息快照。现在发送时先生成本地用户消息，按会话保存；刷新快照不会删掉它。服务端相同轮次的同一消息出现时合并，避免重复。请求明确失败后恢复输入；网络异常且无法确认服务端状态时显示“发送结果待确认”，先刷新核对，避免重复提交。旧时间戳的快照不能覆盖新状态。

SQL 错误不只是模型能力问题。实际 SQLite 的 Orders 状态为 Shipped、Pending、Returned、Delivered、Processed、Canceled，旧字段说明却列出 Shipped、Packing、On Road。Order_Items 的状态说明也不一致。示例 SQL 还有双重单引号、错误大小写 `pending`、多余尾引号；产品名称本身是类别，旧例子却额外按连字符截取。这些上下文会诱导错误查询。

## 行为与代价

- 明确业务错误最多自动修正两次；失败或额度耗尽回人工审核，不会无限循环。每次修正需要再生成、执行、评分，因此可能增加延迟和模型费用。
- 评分仍由模型完成，六项检查不是业务正确性的数学证明。总分或检查缺失时保守进入人工审核。
- 当前样例没有金额、单价、数量、成本、库存、支付时间或送达时间；这些问题应说明数据不足，不能硬凑 SQL。
- `business_knowledge.md` 是当前订单样例的业务口径，更换业务库时应同步维护它以及表/字段说明。
- 小目录阈值是 12 张表；更大的目录仍按字段相关性缩小候选范围，后续可结合真实外键补齐关联路径。
- 本次未改示例问题文本或索引字段展示名，现有 Chroma 的文档文本校验仍兼容，不需要为本次修改重建嵌入。

## 验证

88 项 Python 测试通过，1 项 PostgreSQL 集成测试因未配置 TEST_POSTGRES_DSN 跳过。前端生产构建与 TypeScript 检查通过。浏览器使用独立临时接口模拟 8 秒延迟入库、再延迟 12 秒返回结果，确认气泡先出现，完成后不重复。Python 离线回归覆盖 CTE 示例筛选、实际枚举与日期、全部 SQLite 范例执行、Pending 状态匹配、业务自动修正上限、评分高分但检查失败、累计人工意见和解析错误修复。

真实模型端到端验证尚未完成：沙箱内调用返回错误；申请调用配置的模型服务被自动审批拒绝，理由是目的地和可能发送的 schema、SQL、结果上下文未获明确确认。因此不能据此声称模型准确率提升，也不能把网络错误算作有效拒答。

使用方式：重启后端进程，并刷新前端页面。若后端托管生产静态资源，先在 `frontend/` 执行 `npm run build`（本次已构建）。源码与已构建文件均已更新；未提交 Git。

待批准的真实模型验证限定四个问题：没有订单的客户（订单数为零）、按客户统计订单数并保留零订单客户、列出已取消订单及客户姓名、按客户统计销售额（应拒绝不可计算指标）。将使用已配置的 DeepSeek（api.deepseek.com）和阿里云嵌入服务发送样例问题及必要目录上下文；DeepSeek 的评分还可能接收查询列名和最多五行结果，包含样例客户姓名。验证使用独立内存检查点，不改网页会话或业务数据库；存在少量 API 调用费用。
